# Component variants

The portable design model supports `DesignKind.ComponentSet`. Set nodes carry `variants: { properties: string[], defaultId: string | null }`; their immediate component children carry `variant: { property: string, value: string }[]`. A saved set has 1–128 definitions, 1–16 unique properties and one immediate default. Every child has one complete unique combination. Linked instances store the chosen child component ID, so changing a set default does not change existing instances.

Import `DesignVariants` from `nexa-transport/design-variants` for library filtering, default resolution, property options and exact partial-choice matching. Import the typed metadata from `nexa-transport/design-variant-types`. `DesignComponents.plan` supports the six variant authoring actions through the existing component command union. The result is an atomic operation plan for the normal save endpoint; no separate transport or copied instance scene is required. The wire validators retain the metadata in save requests and paged node records.

Partial choices keep unspecified dimensions. An unavailable combination fails explicitly. Switching definitions retains geometry and unambiguous source overrides. Dimension renames retain existing values; adding a dimension assigns Default to every child. Removing dimensions that would collapse combinations is rejected atomically. Duplicating sets remaps defaults and internal references; copying a child creates a distinct tuple. Release removes set metadata while preserving linked definitions. The native implementation and packaged browser implementation are identical.
